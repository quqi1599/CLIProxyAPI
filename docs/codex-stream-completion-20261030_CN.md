# Codex SSE 完成后结束读取（2026-10-30）

旧版 CLIProxyAPI 的 Codex HTTP SSE 执行器在转发 `response.completed` 后仍等待传输层 EOF。若上游保持连接，客户端收到终态后关闭连接，请求汇总会被改记为 `client_gone / 499`；若上游在终态后断流，也可能额外输出读取错误。WebSocket 执行器已有完成后结束行为，HTTP SSE 路径缺少对应处理。

## 修改

仅在明确、合法的 `response.completed` 成功信封经过既有错误分类，并完整转发所有转换结果后，结束读取并关闭本次上游响应。

完成识别要求有效 JSON、唯一的顶层和 response 字段、非空 response ID、`status=completed`，且顶层及 response 中没有非空错误对象。生成文本中的相同字符串、未完成/失败状态、错误信封及重复字段均不获得提前结束处理。既有容量、纯推理空答案与协议错误分类继续优先执行。

本次不增加重试，不更改原生响应帧、工具参数、用量、模型映射或超时策略，也不修改 WebSocket 执行器。

## 本机验证

- 保持上游连接不关闭的合成 SSE：Responses、Chat、Messages 三种输出修复前均持续等待；修复后立即结束且响应体只关闭一次。
- 客户端收到终态后取消：经过真实 Manager 和 Codex 执行器的三协议测试，基线均复现最终状态 499；修复后保留成功状态。
- 终态前读取异常仍然失败；明确终态后的读取异常不污染已完成结果。
- 重复字段、错误、未完成、无 ID、无状态、文本伪终态和畸形 JSON 反例。
- 相关协议/终态错误与上述新增用例执行 10 轮竞态检查通过。

检查结果只证明本机合成场景；生产版本与真实请求验收独立核验。
